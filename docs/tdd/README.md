# tdd/ —— TDD 记录目录

本目录存放**测试驱动开发（TDD）**的过程产物——「红 → 绿 → 重构」每个循环的记录。它回答「测试是不是真的先行」，而不是自说自话。

## 放什么

- `cycles.md`：每个 TDD 循环一条记录——意图、先写的测试、失败形态（红）、最小实现（绿）、重构动作。
- 失败形态值得记录：第一版测试的报错信息正是「需求被翻译成可执行断言」的证据。只写 `.assert x == y` 而不失败过的循环不算 TDD 循环。

## 不放什么

- 测试代码本体（放 `tests/integration.rs`）
- 接口契约（放 `../sdd/interfaces.md`，那是规格）
- 需求复述与范围（放 `../sdd/overview.md`）

## 与其他目录的分工

| 目录 | 回答 |
|---|---|
| `../sdd/` | 系统应该长什么样（规格，先于代码） |
| `../tdd/` | 测试先行的循环怎么走过来的（内部过程） |
| `../../README.md` | 用户怎么用（操作） |

## 写法约定（cycles.md）

```
### C<n> <一句话意图>
- 红：<测试名 + 第一版为什么失败（缺函数/异常/逻辑错）>
- 绿：<让测试通过的最小改动；不引入下个循环才需要的抽象>
- 重构：<如有：抽函数/改名/消重复；没有就写「无」>
```

约束：一条循环只为一件事变绿；大循环（同时涉及两个模块）应拆成两条。只记失败过的循环；绿灯直接通过的「钉子测试」注明其意义即可。
