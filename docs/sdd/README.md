# sdd/ —— SDD（规格驱动开发）文档目录

本目录存放**规格驱动开发**的设计文档：在写代码之前，先把「系统长什么样」写成可读、可对照的规格。

## 放什么

- `overview.md`：系统定义与边界（第 1 步）
- `architecture.md`：模块划分与请求流程（第 2 步）
- `data-model.md`：核心类型与不变式（第 3 步）
- `interfaces.md`：签名与契约（第 4 步）——**实现的唯一权威**
- `decisions.md`：ADR 设计决策记录（第 5 步）
- `risks.md`：风险登记与验证方式（第 6 步）

## 不放什么

- 测试过程（放 `../cycles.md`）
- 测试与需求的映射（放 `../tdd/mapping.md`）
- 用户面向的操作说明（放 `../../README.md`）
- 代码自身能表达的内容（注释即可，规格只写契约层面）

## 顺序规则

**顺序即依赖，允许回跳不允许跳步。** 每一步只回答一个问题，且只使用前面步骤已经定义过的概念：

```
overview → architecture → data-model → interfaces → decisions → risks
```

- 写 `interfaces.md` 时出现的类型，必须在 `data-model.md` 里定义过。
- `decisions.md` 只解释前 4 步中**真实出现过**的选择，每条追得到具体子文档。
- `risks.md` 评估的是前 5 步定下来的系统，每条风险必须有「怎么验证」。

## 子系统子套件

新增子系统按同一六步开**子套件**（如 LLM 子网关的 `llm/`、QQ Bot 子网关的 `qqbot/`），
`interfaces.md` 同样是该子系统的实现权威；根 `interfaces.md` 只描述顶层网关本身，
不重复子系统契约。子系统套件的 ADR 编号独立成段（如 `ADR-L*` / `ADR-Q*`），不与根 ADR 混编。

## 与其他目录的分工

| 目录 | 回答 |
|---|---|
| `docs/sdd/` | 系统应该长什么样（规格，先于代码） |
| `docs/tdd/` | 测试覆盖了什么需求（映射） |
| `docs/cycles.md` | 测试先行的循环怎么走过来的（过程） |
| `../../README.md` | 用户怎么用（操作） |
