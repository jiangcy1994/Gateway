# 概述

> **SDD 第 1 步**：系统是什么、边界在哪里。后续所有步骤以此为范围。

## 一句话定义

top-gateway 是**顶层网关**：把多个子网关按路径前缀挂载在同一入口之下，并提供 REST 管理 API 对挂载关系进行热增删改查。

## 它解决什么

一个机器上跑多个子网关（如 `qqbot-api-gateway` 及其管理后台）时，每个子网关各自占一个端口。top-gateway 把它们收拢到单一入口；两个通用子网关（LLM、QQ Bot）进一步**内嵌**进同一进程，其余按前缀挂载：

```
client ──► top-gateway:8000
              ├─ /llm/*          ──► 内嵌 LLM 子网关（规格见 sdd/llm/）
              ├─ /qqbot/*        ──► 内嵌 QQ Bot 子网关（规格见 sdd/qqbot/）
              ├─ /svc/*          ──► 127.0.0.1:9000  （routes.toml 挂载的外部子网关）
              └─ /__admin/*      ──► 本网关管理 API（不转发）
```

`/llm` 与 `/qqbot` 是**保留前缀**：由内嵌子网关处理，永远不会落到 `routes.toml` 的前缀路由（ADR-L5 / ADR-Q5）。

## 范围内

- 按路径前缀**最长匹配**把请求流式转发到上游（http/https）。
- 两个**内嵌子网关**：`/llm/*`（按协议选 LLM 供应商池，规格见 `sdd/llm/`）、`/qqbot/*`（QQ 机器人三通道接入，规格见 `sdd/qqbot/`）；二者前缀保留，不进前缀路由。
- 管理 API：路由 / 供应商 / 机器人的增删改查（立即生效）、上游健康查看、每路由指标查看、立即探测。
- 路由配置原子持久化到 TOML 文件，重启不丢失。
- 转发请求头过滤（hop-by-hop）、`x-forwarded-host`/`x-forwarded-path` 注入、路由级头注入。
- 管理端点独立密钥鉴权（`X-Admin-Key` 或 `Bearer`）。

## 范围外

- **不做子网关自身的业务鉴权**：客户端的 `Authorization` 原样透传，由子网关自己验证。
- **不做负载均衡 / 熔断 / 重试**：每个前缀只有一个上游；健康检查是**建议性**的——不健康不拦截转发，只标记状态。
- **不做配置文件热监听**：磁盘文件只在启动时读；运行期变更经管理 API（会同步写回文件）。
- **不做 Web 管理界面**：仅 REST API。
- 不重新实现 TLS 终止：上游为 https 时由 reqwest rustls 直接拨号。

## 用户与典型用法

| 用户 | 用法 |
|---|---|
| 服务运维 | 编辑 `routes.toml` 后重启；或调管理 API 热挂载 |
| 子网关开发者 | 把新子网关挂到某个前缀下，立即可访问，无需改 top-gateway 代码 |
| 监控 | 轮询 `GET /__admin/health` 与 `GET /__admin/metrics` |

## 非功能约束

- 技术栈与 `qqbot-api-gateway` 对齐：Rust + axum 0.8 + tokio + reqwest。
- 请求/响应 body **不缓存**：必须能代理大文件与流式接口。
- 单进程、无外部依赖（无数据库、无 Redis）；路由表存内存，持久化靠本地文件。
