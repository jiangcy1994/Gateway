# 设计决策（LLM 子网关）

> **SDD 第 5 步**：ADR 记录。只解释前 4 步中**真实出现过**的选择，每条追得到具体子文档。

| # | 决策 | 背景（为什么需要选） | 备选与后果 |
|---|---|---|---|
| L1 | **内嵌模块**而非独立子网关进程 | 与 top-gateway 既是同一仓库、又共享 axum/tokio/reqwest 栈；独立进程要多一个端口与一套部署 | 备选：独立二进制经 `routes.toml` 挂载。后果：多一跳 HTTP、供应商配置无法共享进程级 client 连接池；且用户明确选择内嵌。代价：`/llm` 前缀被进程保留（见 L5） |
| L2 | **协议透传，按协议选供应商**，不做协议转换 | 三种协议的聊天接口字段差异大（messages/ system prompt/ tool 结构均不同），转换层等于重写一个适配库，错误面巨大 | 备选：入参归一化中转。后果：OpenAI 客户端打不到 Anthropic 供应商——这是范围声明而非缺陷（`overview.md` 范围外）。客户端想要跨厂商，自己用各家 SDK 各连一个协议段即可 |
| L3 | **显式协议段** `/llm/{protocol}/...` | 入站路径必须能无歧义判定协议；嗅探 path（`/v1/messages` vs `/v1/chat/completions`）在新协议加入时立刻脆弱 | 备选：按 path 嗅探。后果：SDK 的 base_url 多写一段（`http://gw:8000/llm/openai`），但换来确定性与可扩展性 |
| L4 | **剩余配额加权随机**，不做加权轮询 / 最小余量优先 | 「剩余配额加权」是需求原文；随机选择无状态、并发友好（无需跨请求维护游标）；加权轮询在权重随消耗动态变化时行为同样不直观 | 备选：nginx 式平滑加权轮询（确定性、无 rand 依赖）或 least-remaining 优先（会瞬间压满单一供应商）。后果：短样本下分布有随机波动，测试以「耗尽即排除」等确定性边界钉住行为 |
| L5 | **`/llm` 前缀保留**，nest 优先于 routes fallback | 内嵌模块与 `routes.toml` 前缀转发的路由决策必须有一个赢家 | 后果：运维在 `routes.toml` 挂 `/llm` 前缀不会生效（被 nest 截流）。已写入 README 与 architecture.md 的「保留前缀」声明；测试 `llm_coexists_with_route_table` 钉住共存语义 |
| L6 | **全满 429 / 无供应商 503 / 未知协议 404**，统一 house 错误体 | 三种「不可服务」原因语义不同：配额耗尽是客户端可重试的（429 语义），无供应商是配置缺失（503），协议段拼错是路径错误（404） | 备选：全部按 OpenAI/Anthropic 原生错误格式返回。后果：错误体不是原生格式，SDK 的错误解析走通用分支（风险 R4 记录）；换来的是与 top-gateway 全局错误格式一致 |
| L7 | **不做失败转移 / 重试** | 重发 LLM 请求可能产生**两次计费**（上游已接受但响应在传输中丢失时），代价高于一次 502 | 备选：仅在「连接失败、未收到任何响应头」时换供应商重试。后果：单供应商故障 → 客户端直接看到 502。可通过多挂同协议供应商 + 客户端侧重试缓解；监控看 `/__admin/llm/metrics` 的错误数（风险 R7） |
| L8 | **SystemOne 留接口桩** | SystemOne 的 usage 字段规格未定；但路由 / 选择 / 转发是协议无关的通用路径 | 桩的精确范围：`Protocol::Systemone` 全程参与（可建供应商、可路由、Bearer 鉴权、流式转发）；**仅 `extract_tokens` 恒返回 0**——即 TPM 加权对 SystemOne 供应商无效。`llm_systemone_stub_forwards_without_token_counting` 钉住此行为；规格明确后只改 `usage.rs` |
| L9 | **复用 `RouteStats`**（按供应商存独立 map），不建新指标体系 | in-flight / 延迟 / 错误计数的需求与路由指标完全同构 | 备选：为供应商写 `LlmStats`。后果：两套计数器、两套快照序列化；独立 map 防止 route id 与 provider id 碰撞串扰 |
| L10 | **`providers.toml` 独立持久化**，不塞进 `routes.toml` | 供应商是独立配置面（协议池而非前缀路由），生命周期与路由无关 | 备选：合并为一个文件。后果：`Route` / `Provider` 两个 serde 结构互相污染；独立文件还可单独做版本管理与权限控制 |
| L11 | **不做客户端鉴权；不做 api_key 脱敏** | top-gateway 的定位是「子网关自己做业务鉴权」；内嵌 LLM 网关沿袭该定位 | 后果：`/llm/*` 对任何能连到端口的人开放、`api_key` 明文出现在管理 API 与磁盘文件。**部署侧义务**：绑定回环 / 前置反代 / 设 `GATEWAY_ADMIN_KEY`。风险 R5 记录 |
